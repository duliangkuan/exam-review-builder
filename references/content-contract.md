# 内容契约

只在开始写作或修订科目内容时读取本文件。

## 目录

```text
course/
├── subject.json
├── sources.json
├── verification.json
├── content/
│   ├── _header.md
│   ├── ch01.md
│   └── ch02.md
├── figures/              # 可选
└── content.md            # assemble.py 生成
```

`content/` 是人工与 Agent 编辑区，`content.md` 是构建产物，不要双向修改。

## 章节写法

开篇应说明材料范围、考试范围、样本缺口和使用方法。每章使用：

```markdown
## 第一章　随机事件与概率

### 1. 条件概率

📖 [S01 p.23–25]

**一句话认识**：已知一件事发生以后，另一件事发生的概率。

> 🧠 大白话：……

**公式与条件**：……

**⚡ 解题步骤**

1. ……
2. ……

**⚠️ 易错反例**：……
```

每个 `###` 考点至少出现一个 `[Sxx 定位]`；通用补充写成 `📎 补充知识`，不要伪造为课程材料内容。

## 元信息

在 `_header.md` 顶部可写：

```text
＠meta 标题=课程名 · 期末复习
＠meta 副标题=教材版本 · 考试范围 · 阶段稿/完成稿
＠meta 说明=依据哪些材料整理；样本缺口是什么
```

注意 `＠` 是全角字符。

## 支持的正文语法

- `#` 至 `####` 标题；
- 段落、粗体、斜体、行内代码、引用、列表、分隔线；
- Markdown 表格；
- 图片：`![图注；来源 S02 第3题](figures/example.png)`；
- 上下标：`x<sub>1</sub>`、`σ<sup>2</sup>`；
- 居中公式：`[[disp:P(B|A)=P(AB)/P(A)]]`；
- 分数：`[[frac:分子@@分母]]`。

图片必须来自用户有权使用的材料或自行制作，并在图注中写来源。构建器会把本地图片转为 data URI，保持 HTML 单文件离线。

## 选择题块

```markdown
::: quiz id=ch01-q01 belong=第一章 cat=概念辨析
Q 下列说法正确的是（　）。
A 选项一
B 选项二
C 选项三
D 选项四
= C
> 解析：为什么 C 正确，也解释关键干扰项为什么错。
> 依据：[S01 p.25]
> 核验：已从空白状态重解；第二次核验通过。
:::
```

规则：

- `id` 全项目唯一；
- 恰好 A–D 四个选项，只有一个正确答案；
- `cat` 必须属于 `subject.json.quiz_cats`；
- 解析必须含来源；
- 未完成第二次核验时写“第二次核验待完成”，并在 `verification.json` 保持待核状态。

## 内容底线

1. 教材、课件、教师范围和真题之间冲突时，不擅自调和；列出冲突及各自来源。
2. 原材料没有的数字阈值、公式条件、案例细节和结论不得补写。
3. 真题频率一律表述为“在已收集的 N 套样本中出现 M 次”，不写“今年必考”。
4. 类比只帮助理解，不能替代正式定义或改变适用条件。
5. 讲义优先重述与结构化，不大段复制教材。
